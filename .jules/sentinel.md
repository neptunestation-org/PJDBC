## 2026-03-03 - [DataMaskingDriver Bypass via Aliasing and LOB Methods]
**Vulnerability:** The `DataMaskingDriver` could be bypassed by aliasing columns (e.g., `SELECT secret AS alias`), because it only checked the label against masking patterns. It also failed to override LOB getter methods (`getBlob`, `getClob`), allowing raw access to sensitive binary/large character data.
**Learning:** Security proxy drivers must ensure total coverage of the delegated interface. Any method returning sensitive data that is not explicitly handled is a potential leak. Label-based getters in JDBC are particularly dangerous if they don't resolve back to the underlying column identity.
**Prevention:** Always refactor label-based getters to delegate to index-based counterparts after resolving the index via `findColumn`. Ensure all interface methods that return data (including LOBs, complex types, and all `getObject` variants) are overridden with 'fail-secure' logic (e.g., throwing `SQLException` for masked columns).
