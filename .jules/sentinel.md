## 2026-04-20 - Robust SQL Comment Handling in Regex Filters
**Vulnerability:** SQL Comment Bypass of Security Filters
**Learning:** Regex-based SQL filters that rely on `\s` or simple leading keyword matches can be bypassed by using SQL comments (`/*...*/` or `--...`) as delimiters or prefixes. Standard Java regex `\s` does not match comments, allowing attackers to hide keywords from patterns like `^\s*INSERT`. Furthermore, when using `Matcher.appendReplacement` to reconstruct SQL that includes original comments, special characters like `$` or `\` in those comments can cause `IllegalArgumentException` or SQL corruption if not properly escaped.
**Prevention:** Use a robust "SQL whitespace" pattern `(?:\\s|/\\*.*?\\*/|--.*?(?:\\n|$))` combined with `Pattern.DOTALL` for all SQL parsing and identifier extraction. Always use `Matcher.quoteReplacement()` when performing transformations that include captured original SQL fragments to ensure special characters are handled safely.
