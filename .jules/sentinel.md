## 2026-05-19 - SQL Comment-Based Security Bypass
**Vulnerability:** Security proxy drivers and SQL transformers (ReadonlyDriver, SchemaValidationDriver, SchemaTransformer, WhereTransformer) relied on `\s+` to delimit SQL keywords and identifiers. This allowed bypasses using SQL comments (`/* ... */` or `-- ...`) which are valid separators in SQL but were not accounted for in the regex patterns.
**Learning:** SQL parsing using simple regex is fragile. Specifically, leading comments could hide DML/DDL operations from `ReadonlyDriver`, and interspersed comments could bypass table/column name detection in `SchemaValidationDriver`.
**Prevention:** Use a robust whitespace/comment pattern like `(?:\\s|/\\*.*?\\*/|--.*?(?:\\n|$))+` and enable `Pattern.DOTALL` to ensure comments are correctly handled as separators. For leading separators, use `^(?:\\s|/\\*.*?\\*/|--.*?(?:\\n|$))*`. Always use `Matcher.quoteReplacement()` when reinserting captured separators in SQL transformations.
