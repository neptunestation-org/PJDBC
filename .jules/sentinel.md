## 2026-07-28 - Hardening SQL Parsing against Comment and CTE-based Bypass in ReadonlyDriver
**Vulnerability:** The `ReadonlyDriver` originally matched SQL statements against DML/DDL/DCL regex patterns anchored with `^\s*`. This allowed attackers to bypass read-only restrictions by prefixing statements with block/line SQL comments (`/*...*/` or `--...`), or using Common Table Expressions (CTEs) like `WITH x AS (DELETE...) SELECT...`.
**Learning:** Regex-based SQL security filters that rely on anchoring to the start of a statement (`^`) are fragile because SQL syntax allows comments, whitespace, and CTE wrappers before the actual data-modifying statements.
**Prevention:** Always parse or sanitize the SQL string to strip out single/double quotes, backticks, and block/line comments character-by-character (using an O(N) state machine to avoid ReDoS) before matching against keywords. Check for forbidden keywords using word boundaries (`\b`) on the cleaned SQL instead of anchored matchers on the raw SQL.
