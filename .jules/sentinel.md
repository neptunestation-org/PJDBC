## 2026-07-17 - ReadonlyDriver Comment and CTE Bypass Vulnerability
**Vulnerability:** Simplistic `^\s*` anchors in `ReadonlyDriver` SQL statement checking allowed malicious write operations to bypass write protections using leading comments (block/line) or CTE `WITH` prefixing.
**Learning:** Naive whitespace matching is easily bypassed in SQL parsers. SQL comments can mask blocked keywords, and CTE `WITH` prefixes structure the statement in a way that regular expression filters expecting starting DML keywords fail to match. Additionally, manual string slicing to report the blocked keyword in the error message is error-prone when comments are prepended.
**Prevention:** Always use robust `PREFIX` and `SEP` regular expression patterns that account for whitespace, multi-line block comments, and line comments, using `Pattern.DOTALL`. Utilize regex capture groups (`Matcher.group(1)`) to extract the exact matching keyword for accurate reporting rather than naive string manipulation.
