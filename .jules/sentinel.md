## 2026-05-28 - [DataMaskingDriver] Hardening and Aliasing Protection
**Vulnerability:** Data masking in `DataMaskingDriver` could be bypassed via SQL column aliasing (e.g., `SELECT secret AS alias`) or by using non-overridden `ResultSet` methods like `getObject(index, Class)`, `getBlob()`, or `getArray()`.
**Learning:** `AbstractResultSet` only provides transformation hooks for a few methods. To ensure robust masking, every data retrieval method in the `ResultSet` interface must be explicitly overridden. Label-based methods must resolve to their index-based counterparts using `findColumn()` to correctly handle aliasing, as the underlying column position is stable while labels are arbitrary.
**Prevention:** 1. Pre-initialize a `boolean[]` of masked column indices in the `ResultSet` constructor. 2. Refactor all label-based getters to delegate to index-based ones. 3. Implement fail-secure overrides for all complex types (LOBs, Arrays, etc.) that throw `SQLException` for masked columns. 4. Ensure `getObject` variants are handled to prevent type-casting bypasses.
