## 2026-05-02 - SQL Comment-Based Security Filter Bypass
**Vulnerability:** Security drivers (`ReadonlyDriver`, `SchemaValidationDriver`) and SQL transformers (`SchemaTransformer`, `WhereTransformer`) used regex patterns that relied on whitespace (`\s+`) or word boundaries (`\b`) to identify SQL keywords. Attackers could bypass these filters by using SQL comments (`/*...*/` or `--...`) as delimiters instead of whitespace (e.g., `SELECT*FROM/*comment*/secret_table`).
**Learning:** Simple regex-based SQL parsing is easily bypassed because SQL allows comments to appear almost anywhere whitespace is permitted. Regexes that only look for leading whitespace or whitespace between keywords fail when comments are used as separators.
**Prevention:** Always use a robust separator pattern that explicitly matches both whitespace and SQL comments: `(?:\s|/\*.*?\*/|--.*?(?:\n|$))+`. Ensure `Pattern.DOTALL` is used so that multi-line comments are correctly handled. For leading checks, use a similar prefix pattern: `^(?:\s|/\*.*?\*/|--.*?(?:\n|$))*`.
