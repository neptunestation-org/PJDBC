## 2026-03-22 - Data Masking Security Bypass via Complex Types
**Vulnerability:** JDBC `ResultSet` proxy drivers (like `DataMaskingDriver`) can be bypassed if they do not override all `get*` methods of the `ResultSet` interface. Specifically, sensitive data in masked columns could be retrieved unmasked using "complex" type getters such as `getBlob()`, `getClob()`, `getArray()`, `getRef()`, etc.
**Learning:** Overriding only common getters (`getString()`, `getInt()`, etc.) is insufficient for data masking security. The JDBC API is extensive, and any non-overridden method that returns data from the underlying delegate represents a potential security leak.
**Prevention:** For security-focused proxy drivers, ensure comprehensive coverage of the delegated interface. For `ResultSet`, this means overriding all `get*` and `getObject()` variants. A "fail-secure" approach (throwing `SQLException` for masked columns when transformation/masking is not feasible) is preferred over allowing unmasked access.
