## 2026-03-30 - Masking Bypass via Column Aliasing and LOB Getters
**Vulnerability:** Data masking in `DataMaskingDriver` could be bypassed by using column aliases in SQL (e.g., `SELECT secret AS alias`) or by using specialized JDBC getters like `getBlob()`, `getClob()`, or `getObject(..., Class)`.
**Learning:** The previous implementation relied on checking the `columnLabel` against masking regexes at the time of retrieval. However, `ResultSetMetaData` provides both the original column name and the label (alias). Also, `AbstractResultSet` only routes a small subset of getters through the `transformValue` hook, leaving LOBs and specialized types as "blind spots" for proxy drivers.
**Prevention:** 1) Resolve column aliases to their underlying column index at the start of the `ResultSet` lifecycle and use an index-based bitset for masking checks. 2) Refactor all label-based getters to delegate to index-based getters via `findColumn()`. 3) Explicitly override EVERY sensitive getter in the JDBC interface (even those returning complex objects) to either mask the data or throw a "fail-secure" `SQLException`.
