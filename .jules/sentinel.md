## 2026-06-09 - DataMaskingDriver Security Hardening
**Vulnerability:** Data masking in `DataMaskingDriver` could be bypassed using column aliasing (e.g., `SELECT secret AS alias`), complex JDBC types (Blobs, Clobs), or generic `getObject(..., Class<T>)` methods.
**Learning:** `AbstractResultSet` doesn't provide a centralized transformation hook for all data types. Specifically, label-based getters must be explicitly refactored to delegate to index-based getters after resolving the index via `findColumn(label)` to ensure masking logic is applied to the underlying column regardless of its alias. Furthermore, `getObject(..., Class<T>)` needs special handling to return masked strings while failing securely for other requested types.
**Prevention:** Always implement both index-based and label-based getters in JDBC proxy result sets. Centralize masking logic in index-based getters and have label-based getters delegate to them. Throw `SQLException` for any data type that cannot be safely masked (fail-secure).
