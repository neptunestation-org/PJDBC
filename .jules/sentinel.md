## 2026-02-27 - Data Masking Bypass via Aliasing and Incomplete Getter Coverage
**Vulnerability:** The `DataMaskingDriver` could be bypassed by using SQL aliases (e.g., `SELECT ssn AS ssn_alias`) because label-based getters checked the label against masking patterns instead of the underlying column's masking state. Additionally, many JDBC `ResultSet` methods (LOBs, complex types, and generic `getObject`) were not overridden, allowing raw data to leak.
**Learning:** Proxy-based security drivers must maintain a mapping of the security state (e.g., `maskedColumns` boolean array) derived at result set initialization and ensure that *all* data-retrieval paths (both index-based and label-based) refer to this state.
**Prevention:** In JDBC proxy drivers, always delegate label-based methods (e.g., `getString(String)`) directly to their index-based counterparts (e.g., `getString(findColumn(String))`) to ensure consistent security policy application. Furthermore, perform an exhaustive audit of the delegated interface to ensure every data-returning method is either transformed or explicitly blocked.
