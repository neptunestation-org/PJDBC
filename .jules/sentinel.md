## 2026-08-01 - SQL Comment and CTE Bypasses in ReadonlyDriver
**Vulnerability:** ReadonlyDriver used simple regex patterns anchored at the beginning of the SQL query to detect DML, DDL, and DCL write operations. This was easily bypassed by using leading block comments (`/* comment */`) or line comments (`-- comment\n`), or by executing a write operation inside a Common Table Expression (CTE) query (e.g. `WITH cte AS (SELECT 1) INSERT INTO table SELECT * FROM cte`).
**Learning:** Naive regular expressions that check the beginning of SQL strings can be easily circumvented using various SQL-compliant prepend styles (comments, whitespaces, nested subqueries, or CTEs). Directly trying to handle comment structures in regex can lead to extreme complexity or catastrophic backtracking (ReDoS) vulnerability.
**Prevention:** Rather than using complex regular expressions to parse SQL or its comments, use an O(N) single-pass state-machine parser (`cleanSql`) that strips out all comments, single/double-quoted literals, and backtick identifiers by replacing them with space/whitespace of equal length. This maintains character indexes and aligns keywords, allowing standard word-boundary patterns (`\b`) to confidently block unsafe operations without false positives on keywords enclosed inside string literals.
