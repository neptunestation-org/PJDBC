## 2026-03-06 - Data Masking Bypass via Specialized Getters
**Vulnerability:** The `DataMaskingDriver.MaskingResultSet` only overrode standard `getString` and `getObject` methods, leaving specialized overloads (e.g., `getObject(int, Class<T>)`) and complex type accessors (e.g., `getBlob`, `getArray`, `getURL`) as direct pass-throughs to the underlying database driver.
**Learning:** JDBC's `ResultSet` interface is extremely large and contains many redundant methods for data retrieval. Any proxy-based security implementation must either override *every* data-returning method or use a generic hook (like `transformValue` in PJDBC's `AbstractResultSet`) that is consistently called by all getters. PJDBC's `AbstractResultSet` only calls its `transformValue` hook for a limited subset of getters.
**Prevention:** When implementing security-critical proxy drivers for JDBC, perform an exhaustive audit of the `ResultSet` interface to ensure all data access vectors are blocked or transformed. Prefer "fail-secure" (throwing `SQLException`) for types that cannot be easily masked or transformed.
