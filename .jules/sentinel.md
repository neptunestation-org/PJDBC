## 2026-02-24 - DataMaskingDriver Alias Bypass and LOB Leakage
**Vulnerability:** Data masking in `DataMaskingDriver` could be bypassed by using column aliases (e.g., `SELECT secret AS alias`). Additionally, LOB types (Blob, Clob, NClob) were not masked, and `getObject(..., Class<T>)` could be used to retrieve unmasked data.
**Learning:** Checking column labels against a blacklist/whitelist is insufficient because labels can be changed by the user. Consistent security enforcement in JDBC proxy drivers should be based on the underlying column index, which is resolved from both names and labels at initialization.
**Prevention:** In `ResultSet` proxies, refactor all label-based getter methods to resolve the column index via `findColumn(label)` and delegate to their index-based counterparts. Ensure all complex JDBC types (LOBs, Arrays, etc.) are explicitly covered by the proxy to avoid unintentional bypasses. Always use `super.getString(int)` instead of typed getters in the proxy when a string representation is needed for masking, to avoid "Data conversion error" from the underlying driver.
