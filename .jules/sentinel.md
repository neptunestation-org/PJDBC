## 2026-04-07 - DataMaskingDriver Bypass via Aliases and Unprotected Types
**Vulnerability:** SQL aliasing (`SELECT sensitive_col AS alias`) bypassed the `DataMaskingDriver` because it checked masking configuration against the provided column label rather than the underlying column index or name. Additionally, LOB types (Blob, Clob) and complex JDBC types (Array, Ref, URL) were not overridden in `MaskingResultSet`, allowing direct access to raw data.
**Learning:** `AbstractResultSet` in PJDBC only routes a subset of getter methods through the `transformValue` hook. Stream-based getters and complex types often bypass common proxy logic. Furthermore, using `columnLabel` for security checks is unreliable due to SQL aliasing.
**Prevention:** Always refactor label-based JDBC getters to delegate to index-based getters after resolving the index via `findColumn`. Ensure total coverage of the `ResultSet` interface by overriding and "failing-secure" (throwing `SQLException`) on any data retrieval method that does not have a defined masking/transformation strategy.
