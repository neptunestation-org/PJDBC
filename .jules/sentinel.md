## 2026-02-11 - Regex-based SQL Parsing Bypasses
**Vulnerability:** `SchemaValidationDriver` used overly simplistic regexes for table and column extraction, allowing bypasses via quoted identifiers (e.g., `"blocked_table"`), comma-separated table lists (e.g., `FROM table1, table2`), and complex expressions where only the first identifier was checked.
**Learning:** Naive regex parsing of SQL is highly fragile. Quoted identifiers and various SQL syntaxes (like comma-separated tables) provide easy bypass vectors if the regex isn't robust. Furthermore, using capturing groups in shared regex fragments can break other patterns by shifting group indices.
**Prevention:** Use a robust `IDENTIFIER_REGEX` that handles various quoting styles and escaped quotes. Always use non-capturing groups `(?:...)` for shared regex components. Use `while(matcher.find())` to ensure all identifiers in a clause or expression are validated, not just the first one. Normalize identifiers by stripping quotes before comparison.
