## 2026-04-18 - [Data Masking Bypass via Column Aliasing and Complex Types]
**Vulnerability:** The `DataMaskingDriver` allowed sensitive data to be retrieved unmasked through column aliases (e.g., `SELECT secret AS alias`), complex JDBC types (Blobs, Clobs, Arrays, etc.), and modern `getObject(..., Class<T>)` overloads.
**Learning:** Security-focused `ResultSet` wrappers must handle the entire interface to be truly effective. Relying on label-based checks in a proxy is insufficient because labels can be changed by the user via SQL aliases. Delegating label-based calls to index-based ones after resolving the index via `findColumn(label)` is a more robust pattern. Additionally, many JDBC drivers (like H2) may throw conversion errors if `getObject(index, Class)` is called with a type they cannot cast to, even if masking would eventually replace the value, so masking logic must check the requested type first.
**Prevention:** Always delegate label-based JDBC calls to their index-based counterparts to ensure consistent security policy enforcement regardless of SQL-level aliasing. Ensure total coverage of the `ResultSet` interface, throwing fail-secure `SQLException`s for any method that cannot be safely masked.
